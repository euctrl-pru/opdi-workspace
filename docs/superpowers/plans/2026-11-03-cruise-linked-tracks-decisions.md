Task 1: Ruling: under cruise_linked pass margin_seconds = link_max_gap_minutes*60 to tracks_touching_window_end — a hole straddling the read end otherwise loses samples with no warning — if wrong, some extra warnings.
Task 2: Ruling: the same-callsign stratum includes blank callsigns and the paper calls it "same or blank callsign" — the rule treats blank as neutral, so these are the controls the callsign check cannot reject, the conservative choice — if wrong, stratum rates read slightly differently.
Task 2: Ruling: a linked hole is a false join if any truth landing or take-off of the airframe falls inside it, not only a landing followed by a take-off — with both edges at cruise, either one proves a stop, and a whole flight inside a hole otherwise read as unknown — if wrong, false joins are overstated, the safe direction. Overrides spec wording.
Task 2: Ruling: negative controls stratify on realised depth and drop repeated holes within a pair; a cut more than 5 min short of its requested depth is dropped — otherwise one hole counts several times and tightens the upper bound without justification — if wrong, fewer controls.
Task 2: Ruling: report a pair-to-control funnel and a per-pair count beside the rule-of-three bound — depths of one pair are not independent — if wrong, more columns.
Task 3: Ruling: the 1% negative-control limit applies among controls whose gap the setting allows, not counting longer ones as passes — otherwise short-gap settings get an easier limit by construction — if wrong, stricter than necessary. Refines the spec's "overall".
Task 3: Ruling: the 1% limit is computed on negative controls at realised depth 30 min or more, among gaps the setting allows; depth-0 controls are reported but not counted — spec itself calls them too easy, and they dilute the bound — if wrong, stricter than necessary, and possibly no setting passes, which is still a valid result.
Ruling 8: Round 2 measures why holes stay split, per population (crossing the box vs other), and a worst-case negative test with the callsign check removed — headline is dominated by short intra-European flights, and the safety result leans on the callsign check — if wrong, one more 40-minute run.
Ruling 9: Round 3 reads edge position from the last non-blank position within 5 min before the hole and the first within 5 min after, implied speed from those samples' times; still fail closed if none — a blank position is a data quirk (a position message arrives later than others), and failing closed there rejected real holes — if wrong, a slightly different speed at a few edges.
Ruling 10: Round 3 picks by flights crossing the box in one track, then total, then more conservative settings — the owner's goal is crossing flights and the total is dominated by short European flights — if wrong, the pick differs only among settings within the safety limits.
Ruling 11: Round 3 sweeps floors 25,000, 18,000, 10,000 ft (one run each) and gaps 360, 480, 600 min — cruise_at_new_edge and long holes are the next biggest losses — if wrong, about 2 h of cluster time.
Ruling 12: Tighten the real-hole limit from 1% to 0.1% of labelled linked holes, and say in the paper this was set after seeing results — a wrong join is silent and worse than a split, and 1% does not separate settings when 400 kt costs 0.35 points of coverage for a ninth of the false joins — if wrong, slightly fewer flights linked.
Ruling 13: Round 4 adds direction-aware edges behind link_directional_edges: new edge below floor allowed if descending, old edge below floor allowed if climbing, with new low-edge negative controls; if the limits fail it stays off and round 3 stands — target population gains up to 13 points — if wrong, about 90 min.
Task 4d: Ruling: low-edge control families count only at direction-on settings, since at direction-off they fail the floor by construction and would dilute the limit — if wrong, counts move one way, reported in their own column.
Task 4d: Ruling: direction-on settings get their own limits for low-edge negatives (1%), low-edge same-or-blank (5%), and real holes linked only by direction (0.1%, under 300 labelled provisional) — pooling with cruise_cruise hid a 10% failure rate — if wrong, direction might be rejected when it is fine, which falls back on round 3.
Task 4d: Ruling: direction alternative needs at least 3 non-NULL vertical rates at the edge; speed ratio is uninformative at a climb edge — one reading should not carry the verdict — if wrong, fewer links.
Ruling 14: Direction-aware edges stay available and default off — gain is small, it adds a hidden-landing path and complexity — if wrong, one flag.
