## Context

`OPDI_MASTER_NEW` holds five independent git checkouts that are currently unrelated on disk:

| Repo | Remote | Branch | Role |
|---|---|---|---|
| `opdi/` | `euctrl-pru/opdi` | `main` | **The deliverable.** PySpark pipeline (v2.0.0), 9 steps, runs on OSN. |
| `opdi-portal/` | `euctrl-pru/opdi-portal` | `feature/new-topics` | Quarto site: concepts, methodology, roadmap. |
| `eurocontrol/` | `eurocontrol/eurocontrol` | `main` | R package over PRISME Oracle. **Ground truth.** |
| `traffic/` | `xoolive/traffic` | `master` | Reference algorithms (v2.13+75). |
| `prc-data-challenges/` | *(not a repo)* | — | 4 checkouts: 2024/2025 challenge + winners. |

Three concrete problems motivate this work.

**1. Trajectory cleaning is close to absent.** The pipeline applies only three things, and they live in two different steps:

- at **ingestion** (step 01) — a Europe bbox and a 5-second decimation, `event_time % time_interval == 0` with `time_interval=5`, which *drops* rows rather than resampling ([osn_statevectors.py:92-108](opdi/src/opdi/ingestion/osn_statevectors.py#L92-L108));
- at **tracks** (step 02) — a conditional altitude replacement, a centred ±5 min rolling mean applied only where `|ROC| > 25.4 m/s` ([tracks.py:254-320](opdi/src/opdi/pipeline/tracks.py#L254-L320)).

There is **no** lat/lon outlier rejection, no stale-broadcast detection, no isolated-point removal, no dedup of state vectors. Both PRC winners treated exactly these as the foundation of their pipelines, and the 2025 organizers explicitly graded teams on it.

**2. The event vocabulary does not reach the GANP milestones.** Four detectors produce ~16 type strings. Take-off and landing are **pure phase-transition heuristics** — `prev_phase == "GND" AND next_phase == "CL"` ([events.py:209-216](opdi/src/opdi/pipeline/events.py#L209-L216)) — with no runway anchoring, no ground-speed gate, and no use of the `on_ground` flag that is already in the schema. `opdi_h3_airspace_ref` is generated by step 00c and **never read by anything**.

**3. ADEP/ADES detection has known gaps.** `_categorize_landing_take_off` ([flights.py:207-264](opdi/src/opdi/pipeline/flights.py#L207-L264)) classifies a track-airport pair by counting the *sign* of a 5-sample rolling-mean altitude difference and requiring a margin of 4 counts. It ignores `on_ground`, ignores `vert_rate`, ignores the `min_c_radius_nm`/`max_c_radius_nm` ring bands that `h3_airport_zones` already computes, and anything that fails the margin becomes `"ambiguous"` and is **dropped entirely** ([flights.py:282](opdi/src/opdi/pipeline/flights.py#L282)). A flight seen only above FL40 near its origin, or with a noisy altitude trace, silently loses its ADEP.

Cross-cutting: **there is no `tests/` directory anywhere in `opdi`**, despite `pyproject.toml` configuring `testpaths = ["tests"]`. Nothing is validated against ground truth today.

### Decisions taken

- **Hybrid cleaning architecture** — native Spark for the bulk path; an opt-in `applyInPandas` escape hatch for algorithms with no Spark equivalent.
- **Extend `opdi` in place** — no new packages. New subpackages inside `src/opdi/`.
- **First milestones**: ATOT/ALDT + runway ID (≈T08/T17), 40/100 NM rings — an **APDF/ASMA construct, not GANP T11/T14** (§3d) — and **improved ADEP/ADES detection**.
- **Meta-repo with submodules** for the workspace.

## Part 2 — Trajectory cleaning: `src/opdi/cleaning/`

New subpackage, inserted as **step 02a** between tracks (02) and flight list (03), operating on `osn_tracks`.

### 2a. Native Spark path (always on) — `cleaning/native.py`

Follow Alligier's (2024 winner) design: **mask bad values to NULL, keep the row**. This preserves irregular timestamps, avoids row explosion, and keeps "no data" distinguishable from "interpolated data". It is also the only approach that is pure column-expression work.

Ordered stages, each a `DataFrame.transform`-able function:

1. **Dedup + ordering** — drop duplicate `(track_id, event_time)`, keep first.
2. **Range validity** — NULL out `lat ∉ [-90,90]`, `lon ∉ [-180,180]`.
3. **Stale-broadcast removal** — ADS-B updates position and velocity fields in separate message types; identical consecutive values mean *repeated*, not *measured*. Three `lag()` comparisons per Alligier's `FilterCstLatLon`/`FilterCstPosition`/`FilterCstSpeed`:
   - neither `lat` nor `lon` changed → NULL both
   - none of `lat`/`lon`/`baro_altitude` changed → NULL all three
   - none of `vert_rate`/`heading`/`velocity` changed → NULL all three
4. **Derivative spike filter** — port `MyFilterDerivative` with its **≥2-vote kill rule**: a point dies only if it participates in ≥2 flagged derivative windows. Uses real Δt, computed over *valid* values only (Alligier compacts NaNs out before differencing, so a plain `lag()` is wrong — it would span rows an earlier stage already NULLed). `heading` needs unwrapping (period 360); a shortest-angular-difference expression is equivalent and avoids a cumulative pass.

   **Thresholds stay in aviation units** — OPDI publishes in ft/kt/FL, and these are the numbers Alligier states. Storage stays SI: the filter's only output is a NULL mask, and a mask carries no unit, so each column is scaled into its aviation unit purely to evaluate the comparison and the mask is applied to the untouched SI column. Nothing is converted on disk.

   | column | 1st deriv | 2nd deriv | scale factor from SI |
   |---|---|---|---|
   | `baro_altitude` | 200 ft/s | 50 ft/s | ×3.28084 (m→ft) |
   | `geo_altitude` | 200 ft/s | **150 ft/s** | ×3.28084 (m→ft) |
   | `vert_rate` | 1500 ft/min/s | 1000 ft/min/s | ×196.850394 (m/s→ft/min) |
   | `velocity` | 12 kt/s | 10 kt/s | ×1.94384 (m/s→kt) |
   | `heading` | 12 °/s | 10 °/s | — |
   | `lat`/`lon` | 0.01 °/s | 0.06 °/s | — |

   Three corrections against the source, all of which would have been silent (`filterclassic.py`):
   - **Votes are tallied per derivative order and OR-ed** (`killa>=2 or killv>=2`, line 191), never summed. Summing lets one 1st-derivative vote plus one 2nd-derivative vote kill a legitimate step change — the exact case the rule exists to protect.
   - **Both derivatives carry the same unit**, `[column]/s`. The 2nd is a difference of *raw* differences over a mean timestep (line 181), not a rate-of-a-rate, so it never acquires an `s²`.
   - **`geo_altitude` takes a looser 2nd threshold than `baro_altitude`** (150 vs 50, lines 139-140) because GNSS is noisier. Do not collapse them into one altitude row.

   Caveat on "spares legitimate step changes": it spares steps *between* the two thresholds. A step exceeding the 2nd-derivative threshold is still killed. The margin between d1 and d2 **is** the manoeuvre tolerance — which is why lat/lon sets d2 six times higher than d1.

5. **Isolated-point removal** — per column, NULL where the value is >20 s from any other valid value of that column: `dt = min(t − t_prev_valid, t_next_valid − t)`.
6. **Gap segmentation** — a `segment_id` on 5-minute gaps, so downstream detectors never interpolate across a coverage hole.

All expressible with `Window.partitionBy("track_id").orderBy("event_time")` — the same idiom the repo already uses.

**Config**: a `CleaningConfig` dataclass in [config.py](opdi/src/opdi/config.py) with every threshold named, so nothing is a magic number and the benchmark can sweep them.

**Explicitly do NOT port** (documented negative results, cite in the paper):
- Synthetic gap filling — *"Attempts to complete the trajectory always lead to worse result"* (2025 report §7).
- GPS-jamming removal — leaving jamming untouched scored better (2025 report §7).
- Wind/ERA5 enrichment — removing wind *improved* RMSE 201.04 → 199.91 (Table 4).

> subset-font encoded and could not be text-extracted on the OSN/dev boxes (no
> `poppler`/`pypdf`). The *conclusions* are nonetheless corroborated directly by the

> **commented out** at [data.py:126](prc-data-challenges/2025/resourceful-quiver/src/resqu/data.py#L126),
> and `.get_wind(meteo_grid)` / `.tas_from_wind()` are **commented out** at
> [preprocessor.py:616-617](prc-data-challenges/2025/resourceful-quiver/src/resqu/preprocessor.py#L616-L617).

## Part 3 — Milestones: `src/opdi/pipeline/milestones/`

### 3a. Improved ADEP/ADES detection (highest value — fixes flight list gaps)

> **Researched 2026-08-05.** Seven methodologies benchmarked against APDF on
> 2025-06-05 (32,404 flights, 35.4 M state vectors). Harness:
> `opdi/benchmarks/adep_ades.py`; write-up:
> `opdi-portal/papers/adep-ades-detection/`. Several hypotheses below were
> **falsified** — they are kept, struck through, with what was measured.

Rewrite `_categorize_landing_take_off` and `_compute_flight_table` in [flights.py](opdi/src/opdi/pipeline/flights.py). The measured conclusion is that the evidence-scoring model this section originally proposed is the wrong shape: **no vertical-trend signal improves on "nearest aerodrome to the track endpoint" on the flights where both fire.** What the trend logic actually supplies is abstention, and supplying it explicitly is both simpler and strictly better.

- ~~**Use `on_ground`** — the single strongest signal available.~~ **Falsified.** On-ground evidence (M2) covers only 24.76% of flights, and in a precision-ordered cascade it is 7.92% accurate on the flights it uniquely answers, against 47.08% for the endpoint rule on the same flights. Ground reception is too sparse and too often present at only one end of a track.
- ~~**Use `vert_rate`** — far more robust than differencing a smoothed altitude.~~ **Half right.** M3 does beat the production algorithm (57.42% coverage / 97.39% accuracy vs 54.78% / 98.25%), so `vert_rate` is the better of the two trend signals — but it is still dominated by endpoint proximity, losing 8 points of accuracy to it on its own flights.
- ~~**Use the ring bands.**~~ **Unlikely to help.** Radius is nearly inert: sweeping the endpoint distance threshold from 10 NM to 40 NM moves ADEP coverage by 0.2 pp. Effort spent on ring geometry buys almost nothing.
- **Raise the altitude ceiling adaptively** — **confirmed, and it is the dominant parameter.** The right form is height **above field elevation**, not flight level: a fixed cut means nothing at an aerodrome at 5,000 ft. Moving the cut from on-ground-only to 5,000 ft AGL moves ADEP coverage by 34 pp.
- **Replace "ambiguous → drop" with a confidence score** — **confirmed, and this is the whole of the problem.** Coverage, not accuracy, is what the current algorithm gets wrong; it is the second most accurate method tested and fifth by overall correctness.
- **Retain `ADEP_P`/`ADES_P`** runner-up semantics already documented in the portal methodology.

**Implementation to adopt** (pending full-month confirmation): nearest aerodrome to the track's first/last sample, emitted only when that endpoint is within *d* NM of the aerodrome and no more than *h* ft above its elevation. At *d*=10 NM, *h*=5,000 ft this gives **58.79% ADEP coverage at 99.40% accuracy**, beating production on both axes at once. Both parameters should be published with the flight list, and the abstention reason retained per flight so consumers can distinguish "no departure aerodrome" from "not determinable".

**Still open before implementing:** full-month runs for 2024-06 and 2025-06 (fit on one, validate on the other); the cleaning ablation (§2 may *remove* the gate samples this method depends on — the stale-broadcast filter nulls repeated positions, which is what a parked aircraft transmits); per-aerodrome arrival/departure counts vs APDF; and the aerodrome-set sweep.

### 3b. ATOT / ALDT with runway ID (≈T08 / T17)

Do **not** rewrite runway geometry — v0.0.2 already emits `entry-runway`/`exit-runway` via HexAero H3 res-12 matching, with the OSM runway designator carried in `info.osm_ref` ([events.py:365-490](opdi/src/opdi/pipeline/events.py#L365-L490)).

New detector that anchors on those events:
- **ATOT** = last sample inside the runway polygon before a sustained positive ROC, cross-checked against `on_ground` transition and a ground-speed gate (traffic's `TrackBasedRunwayDetection` uses `min_groundspeed_kts=30`, `min_vert_rate_ftmin=257`).
- **ALDT** = first sample inside the runway polygon after a sustained negative ROC / on-ground transition.
- Promote `osm_ref` to a first-class `runway` field in `info`, so it is directly comparable to APDF `AP_C_RWY`.
- Emit as new types `ATOT`/`ALDT` under a new `version` string; **keep the existing `take-off`/`landing` types unchanged** so published v0.0.2 data is not disturbed.

### 3c. 40 NM / 100 NM rings (APDF/ASMA — **not** GANP T11/T14)

These rings are a **PRU/APDF operational construct** (the ASMA ring set), chosen here because
APDF gives a direct column-to-column benchmark. They are *not* GANP T11/T14, which are
airspace-boundary crossings — see §3d. Treat a ring crossing as a usable *proxy* for terminal-
airspace entry, and say so explicitly in the paper rather than labelling it T14.

`h3_airport_zones` already generates rings at `[0, 5, 10, 20, 30, 40]` NM ([h3_airport_zones.py:190](opdi/src/opdi/reference/h3_airport_zones.py#L190)) — **extend `radii_nm` to include 100**. Note that both `prepare_for_flight_list` and its Spark twin default to `max_radius_nm=30.0` and `runner.py:92` passes `30`, so the 40 NM band is *already* being discarded downstream ([h3_airport_zones.py:401](opdi/src/opdi/reference/h3_airport_zones.py#L401), [:476](opdi/src/opdi/reference/h3_airport_zones.py#L476)) — that ceiling has to be raised to 100 as well, in both places, or the new rings never reach the detector.

Detect the crossing sample per (track, airport, ring, direction), interpolating the crossing time between the bracketing samples rather than snapping to the nearest one.

Emit `entry-40nm` / `exit-40nm` / `entry-100nm` / `exit-100nm` with lat/lon/FL/bearing in `info`, matching APDF's `C40_CROSS_{TIME,LAT,LON,FL}` / `C40_BEARING` field set exactly so the benchmark is a direct column-to-column comparison.

## Part 4 — Benchmarking against EUROCONTROL ground truth

`opdi` has **zero tests today**. Create `tests/` (already configured in `pyproject.toml`) plus a `benchmarks/` module.

### Ground-truth mapping (from `eurocontrol/R/airport_operator_data_flow.R`)

APDF is in **long/movement form** — there is no literal AOBT/ATOT column. Discriminate on `SRC_PHASE`:

| OPDI milestone | APDF column | Filter |
|---|---|---|
| AOBT | `BLOCK_TIME_UTC` | `SRC_PHASE == 'DEP'` |
| **ATOT** | `MVT_TIME_UTC` | `SRC_PHASE == 'DEP'` |
| **ALDT** | `MVT_TIME_UTC` | `SRC_PHASE == 'ARR'` |
| AIBT | `BLOCK_TIME_UTC` | `SRC_PHASE == 'ARR'` |
| **Runway** | `AP_C_RWY` | — |
| Stand | `AP_C_STND` | — |
| **40/100 NM rings** | `C40_/C100_CROSS_{TIME,LAT,LON,FL}`, `_BEARING` | — |

**ADEP/ADES** ground truth comes from `flights_tidy()`: `ADEP`/`ADES`, joined via `AIRCRAFT_ADDRESS` (= `icao24`) + `AIRCRAFT_ID`/`AP_C_FLTID` (= callsign) + date.

### Design

- `tests/` — unit tests on synthetic trajectories with **known** injected defects (a lat spike, a stale broadcast run, a 20 s isolated point). These must run without Spark cluster access, using a local session.
- `benchmarks/` — reproducible scripts that join OPDI output to `reference/*.parquet` and emit metrics:
  - **ATOT/ALDT**: median and IQR of signed time error; % within ±30 s / ±60 s.
  - **Runway**: exact-match rate against `AP_C_RWY`.
  - **Rings**: time error + great-circle position error vs `C40_CROSS_LAT/LON`.
  - **ADEP/ADES**: precision/recall/accuracy, and critically **coverage** — the fraction of ground-truth flights for which OPDI produces *any* ADEP/ADES. This is the number that quantifies the current gaps.
- Every benchmark writes a versioned parquet of per-flight results, so the paper renders from a committed cache with no DB access — matching the portal's existing offline-render guarantee.
